# N2 — Security kernel

Read `graph/specs/_common.md` first. Then read, in full:

- `kernel/contract.ts` — the public contract you implement (types, constants, doc comments).
- `kernel/tests/acceptance/*.ts` — your fixed evaluator (5 test files + `helpers.ts`).
- `node_modules/@noble/post-quantum/README.md`, `hybrid.d.ts`, `ml-dsa.d.ts`, `utils.d.ts` —
  the post-quantum library API. Do not guess call shapes; read them.

## You own

`kernel/src/**` and `kernel/tests/unit/**` (optional extra tests). Nothing else.

## Goal

A small, framework-free security core that runs unchanged in the browser and in Node ≥ 22.
It owns key material, encrypts data at rest, enforces least privilege between first-party
modules, keeps a tamper-evident audit trail, and validates untrusted input. It will be read
by a security reviewer: keep it small, direct and boring. Roughly 900–1300 lines across the
files below is the right size.

Suggested layout (one concern per file): `index.ts` (public entry, re-exports), `errors.ts`,
`bytes.ts` (base64 / utf8 / canonical JSON), `webcrypto.ts`, `pq.ts`, `selftest.ts`,
`storage.ts`, `audit.ts`, `vault.ts`, `capabilities.ts`, `validate.ts`, `iban.ts`,
`kernel.ts`.

## Public entry — `kernel/src/index.ts`

Must export every member of `KernelModule` (see contract), plus:

- `class KernelError extends Error` with `readonly code: KernelErrorCode`.
- `class CapabilityError extends KernelError` with `code: 'DENIED'`, `moduleId`, `capability`.
- Everything from the contract, re-exported, so consumers import only this file:
  `export * from '../contract.ts';` (constants and types).

Error messages are short English diagnostics. They never contain passphrases, keys, plaintext
or ciphertext.

## Cryptography

Classical primitives come from **WebCrypto** (`globalThis.crypto.subtle`), which is native and
keeps keys non-extractable. Post-quantum primitives come from `@noble/post-quantum`.

| Purpose | Algorithm | Source |
|---|---|---|
| Hash | SHA-256 | `crypto.subtle.digest` |
| Data + key-wrap AEAD | AES-256-GCM, 96-bit random nonce, never reused | `crypto.subtle` |
| Passphrase KDF | PBKDF2-HMAC-SHA-256, ≥ 600 000 iterations, 16+ byte random salt | `crypto.subtle` |
| Envelope KDF | HKDF-SHA-256 | `crypto.subtle` |
| KEM | X-Wing: `ml_kem768_x25519` | `@noble/post-quantum/hybrid.js` |
| Signature | `ml_dsa65` | `@noble/post-quantum/ml-dsa.js` |
| Randomness | `crypto.getRandomValues` only | — |

Rules:

- Look up `globalThis.crypto.subtle.<fn>` **at call time**. Do not capture bound references to
  WebCrypto functions at module load (the self-test must observe a broken primitive; one test
  replaces `subtle.digest`).
- `Math.random` must not be reachable from any kernel code path.
- AES keys are imported as **non-extractable** `CryptoKey`s. Raw key bytes that had to exist
  briefly (the data key before wrapping, a KEM shared secret, the audit signing key) are
  overwritten with zeros as soon as they are no longer needed, and on `lock()`.
- Normalise passphrases with NFKC before use. Strength rule is length only: fewer than
  `MIN_PASSPHRASE_LENGTH` code points → `WEAK_PASSPHRASE`.

### Vault format

- **Header** (`STORAGE_KEYS.header`, type `VaultHeader`): created by `initialize()`.
  A random 256-bit data key (DEK) is wrapped with the passphrase-derived key (KEK) using
  AES-256-GCM. The AEAD associated data is a canonical encoding of **all other header
  fields** (`v`, `kdf.name`, `kdf.iterations`, `kdf.salt`, `auditPublicKey`, `createdAt`), so
  changing any of them makes the unwrap fail.
- **Records** (`STORAGE_KEYS.recordPrefix + collection + '/' + id`): JSON `{ v: 1, iv, ct }`
  (base64). Plaintext is the UTF-8 JSON of the value. Associated data binds the record to its
  location (collection and id), so a ciphertext moved to another key fails to decrypt.
- The ML-DSA-65 **audit signing key** is generated by `initialize()`, stored encrypted under the
  DEK in a kernel-reserved location (reserved names start with `_`, which no module name rule
  can match), and held in memory only while unlocked. Its public key goes in the header.

`unlock()` order: no header → `NOT_INITIALIZED`; header JSON malformed → `INTEGRITY`;
`kdf.iterations < MIN_KDF_ITERATIONS` → `KDF_TOO_WEAK` **before any key derivation**; unwrap
fails → `BAD_PASSPHRASE` (a wrong passphrase and a tampered header are indistinguishable;
either code is accepted by the tests for tampering). A failed unlock appends
`kernel.unlock_failed` and leaves the state `locked`.

### Sealed envelopes (`pq.seal` / `pq.open`)

`seal`: X-Wing encapsulate to the recipient → HKDF-SHA-256 over the shared secret (info string
includes the `alg` label and envelope version; salt = the KEM ciphertext) → AES-256-GCM key →
encrypt with a random 96-bit nonce. Associated data = caller `aad` (empty when omitted),
length-prefixed, plus the `alg` label. `open` reverses it and maps **every** failure (wrong
key, wrong length, bad base64, wrong `alg`/`v`, aad mismatch, tampering) to
`KernelError('BAD_ENVELOPE')`. `seal` with a malformed recipient key also rejects
`BAD_ENVELOPE`. `pq.verify` resolves `false` for any malformed input instead of throwing.
`pq.sign` / `pq.verify` use ML-DSA-65 with the library's default (hedged) signing.

### Backups

`admin.exportBackup(pk)` seals a JSON snapshot of every storage key under `shaheen/` (they
are already ciphertext / public data) with aad `shaheen/backup/v1`. `restoreBackup(storage,
sk, envelope)` opens it first, then requires the target to hold no key under `shaheen/`
(`NOT_EMPTY`), then writes. On any failure nothing is written.

## Kernel behaviour

- `createKernel(options)` is async: it reads the header to decide `uninitialized` vs `locked`.
- `selfTest()` runs known-answer / round-trip checks for the six `SelfTestId`s, catching
  exceptions per check (it never throws), records `kernel.selftest {ok}`, and stores the
  result. `initialize()` / `unlock()` reject `SELFTEST_REQUIRED` if it never ran in this
  instance and `SELFTEST_FAILED` if the last run failed. Use real vectors:
  - SHA-256("abc") = `ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad`
  - PBKDF2-HMAC-SHA-256("password", "salt", 1 iteration, 32 bytes) =
    `120fb6cffcf8b32c43e7225256c4f837a86548c92ccc35480805987cb70be17b`; 2 iterations =
    `ae4d0c95af6b46d32d0adff928f06dd02a303f8ef3c251dfd6e2d85a95474c43`
  - AES-256-GCM: encrypt/decrypt round trip **and** a flipped ciphertext bit must fail.
  - `ml-kem-768-x25519`: encapsulate/decapsulate agree; a corrupted ciphertext yields a
    different secret (or throws).
  - `ml-dsa-65`: sign/verify succeeds; a modified message fails.
  - `csprng`: two 32-byte draws differ and are not all zero.
- `initialize(passphrase)`: `ALREADY_INITIALIZED` if a header exists; `KDF_TOO_WEAK` if
  `options.kdfIterations` is below the minimum; writes the header; appends
  `kernel.initialized`; ends `unlocked`.
- `lock()`: when unlocked, append `kernel.locked`, **then** sign a checkpoint that covers it,
  then drop and zero key material, set `locked`, notify subscribers. No-op when not unlocked.
- Idle lock: see `KernelOptions.idleLockMs` in the contract. Applied by `tick()` and lazily at
  the start of every vault/admin operation.
- `subscribe(listener)` is called with the new state on every transition; returns unsubscribe.

### Capabilities and handles

- `grant(moduleId, caps)`: validate `moduleId` (`NAME_RULES.moduleId` → `INVALID_NAME`); every
  capability must be exactly one of the documented forms with a name that passes the matching
  `NAME_RULES` pattern, otherwise `INVALID_CAPABILITY` (so no wildcards, no reserved
  collections). A failed grant does not consume the module id. Second grant for the same id →
  `DUPLICATE_MODULE`. After `seal()` → `SEALED`.
- The handle and each of its sub-objects (`capabilities`, `vault`, `audit`, `admin`) are
  `Object.freeze`d. The capability list is copied at grant time. The handle is a thin object of
  closures: no key bytes, `CryptoKey`s or long strings are reachable from its properties.
- Order of checks for a vault call: name validation (`INVALID_NAME`) → capability
  (`CapabilityError`, and append `capability.denied {capability}` with the module as actor) →
  idle/locked (`LOCKED`) → operation.
- `vault.put` / `vault.delete` append `vault.put` / `vault.delete {collection, id}` (actor =
  module). Never the value.
- `handle.selfTest()` is open to every module.
- `audit.entries()` / `audit.verify()` need `audit:read` and work while locked.
  `audit.log(action, detail)` is open to all; `action` must match `NAME_RULES.auditAction`
  (`INVALID_NAME`).
- `admin.*` needs `kernel:admin`. `checkpoint()` and `exportBackup()` need an unlocked kernel
  (`LOCKED`). `info()` and `auditPublicKey()` work while locked.
  `info().pqLibrary` = `{ name: '@noble/post-quantum', version: <from its package.json or a
  constant kept in sync>, independentlyAudited: false }` — that flag is deliberate.

### Audit trail

- One entry per storage key: `STORAGE_KEYS.auditPrefix + seq padded to 10 digits`, value =
  the `AuditEntry` JSON. `hash` = SHA-256 hex over a canonical encoding (sorted keys) of
  `{seq, ts, actor, action, detail, prevHash}`. `prevHash` of entry 1 is 64 zeros.
- **Append from storage, not from memory**: read the current head from storage for each
  append, because another kernel instance (another tab) may have appended in between.
  Serialise this instance's appends with an internal promise queue so they never interleave.
- Entries can be appended in any state, including `uninitialized` and `locked`.
- Checkpoint: `STORAGE_KEYS.checkpointPrefix + padded seq`, value = `AuditCheckpoint`; the
  signature covers a domain-separated encoding of `(seq, hash)`.
- `verify()`: walk entries from 1; a missing sequence number, wrong `seq`, wrong `prevHash` or
  wrong recomputed `hash` fails at that sequence number (`firstBadSeq`). Then every checkpoint
  must refer to an existing entry with the same hash and carry a valid signature under the
  header's `auditPublicKey`; otherwise `ok: false`. `signedThrough` = highest valid checkpoint.
  With no header (uninitialised), checkpoints cannot exist and are not required.

## Validation helpers

- `validateIban`: remove spaces, upper-case. Reason order: `empty` → `chars` (anything other
  than ASCII letters/digits after removing spaces) → `country` (first two characters are not
  letters, or not a code in the IBAN registry) → `length` (per-country length) → `checksum`
  (ISO 13616 mod 97 ≠ 1). Include the full registry length table (it must contain at least
  SA 24, AE 23, EG 29, GB 22, DE 22, QA 29, KW 30, BH 22, JO 30, LB 28, TR 26, FR 27, NL 18).
- `maskIban`, `boundedText`, `parseModelJson`: see contract and `validate.test.ts`.
  `parseModelJson`: for `object` schemas unknown keys are dropped; for `record` schemas a key
  outside the allow-list is a failure. Build results from validated values only — never copy
  from the parsed input by key enumeration, and never assign `__proto__`, `constructor` or
  `prototype`. Cap the input length (reject text longer than 200 000 characters).
